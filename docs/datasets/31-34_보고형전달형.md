# 31 ~ 34 보고형·전달형 리포트 가상 ISP 데이터 — 정의서 (생성 완료)

> 2026-11-10 작성. 사용자 요청: "실무자가 임원에게 보고하는 느낌의 리포트와, 임원이 실무자에게 알려 주는 느낌의 리포트 두 가지 타입. 데이터는 가상의 데이터를 만들어서 쓰고, 각각 상위 메뉴로".
> 쓰는 곳: 메뉴 **보고형 리포트**(`app_pages/up/`, 5개) · **전달형 리포트**(`app_pages/down/`, 5개). 계산은 `utils/brief.py`.
> 만드는 스크립트: `scripts/gen_brief.py` (4개 파일을 한 번에, seed 2026 고정, 약 2분). 계약 하나하나를 한 달씩 움직여서 네 파일의 숫자가 서로 맞는다.
> 사용자가 가상 데이터를 만들어 쓰라고 해서 컬럼 확정 전에 만들었다. 컬럼·패턴은 사용자가 화면을 보고 고친다.

## 가상 회사

- 케이블 ISP. 본부 3개(서울·경기·지방) × SO 4곳 = **SO 12곳**, 2023년 말 계약 약 5만 건.
- 사업 2개(인터넷·TV) × 고객유형 2개(개인·기업) = 묶음 4개. 약정 12·24·36개월.
- 2024-01 ~ 2025-12 (24개월). 화면 기준월은 **2025년 12월 하나로 고정**한다 (자료 마지막 달).
- 2025년부터 **만료 고객 관리**(약정이 끝나는 고객에게 담당자가 연락하고 혜택을 제안)를 시작했다. SO마다 담당자 3~4명.
- 금액은 원, 가공 없음. 실제 데이터(z91~z99)와 섞지 않는다.

## 화면 규칙 (2026-11-10 정함)

- **보고형**(실무자 → 임원): 합니다체. 결론 한 문장 → 숫자 카드 → 근거 → 어디서 → 위험 → 대응안(추정) → **결정해 주실 것**(번호 목록, `decision()`). 회사 전체를 본다.
- **전달형**(임원 → 실무자): 해요체. **SO 하나를 고른다** (`?so=수원`, SO 담당자에게 링크로 보낸다). 회사 중점 → 우리 SO 위치(12곳 중 순위) → 할 일(`todo()`, 명단 링크) → 명단.
- 같은 숫자는 두 메뉴가 같은 함수로 계산한다 (예: 1~3월 예상 해지 = `plan()`·`plan_sum()`, 한 주 연락 건수 = `pace()`).
- 담당자 이름은 가운데 글자를 가린다. 담당자 화면은 순위가 아니라 서로 배우는 용도라고 화면에 적는다.

## 확인할 것

- 30일 전 연락 효과의 근거가 대부분 수원 SO에서 나온다. 다른 SO가 같은 효과를 낸다는 가정이라 화면에 적었다.
- 연락한 고객과 안 한 고객은 처음부터 다를 수 있다 (선택 편향). '지킨 계약'은 차이를 모두 연락 효과로 본 추정이다.
- 기준월 선택(2025년 12월 말고 다른 달)은 아직 없다. 필요하면 33을 달마다 만들어야 한다.
